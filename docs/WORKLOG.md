## 2026-10-16 — план Windows dev-сборки

План: добавить Windows UCRT64 в матрицу GitHub Actions. Для OpenSSL брать готовый пакет MSYS2: при каждом запуске обновлять сведения о пакетах, сравнивать доступную версию с ключом кэша и скачивать пакет только при смене версии или отсутствии кэша. Адаптировать загрузку PKCS #11 DLL к Windows, собрать модуль и проверить его загрузку. По решению владельца Windows архив содержит только провайдер и `pkcs11.h`; DLL OpenSSL туда не входят. Отдельно проверить и документировать источник OpenSSL для macOS.

Сделано: изучены workflow, упаковка и POSIX-зависимости кода. Добавлены загрузка драйвера через Windows API, экспорт точки входа провайдера, пропуск обработчиков `fork`, сборка UCRT64 и кэш готового пакета OpenSSL по версии. Linux сборка и оба прямых unit-теста локально прошли. Проверка Windows на GitHub ещё предстоит.

Дальше: проверить Windows runner, повторить выпуск пяти архивов в GitHub Release.

Первый запуск на GitHub: четыре существующие платформы прошли сборку, Windows
остановился до компиляции. `setup-msys2` установил OpenSSL транзитивно и
очистил кэш pacman, поэтому архив для нашего отдельного кэша отсутствовал.
Переставлены шаги: после проверки версии сначала восстанавливается архив,
затем обновляются и устанавливаются MSYS2-пакеты. Если пакет уже установлен,
`pacman -Sw` скачивает файл для кэша. На macOS ARM64 у готового модуля
подтверждена зависимость от Homebrew `libcrypto.3.dylib` по пути `opt`.

Второй Windows job остановился на обновлении MSYS2 runtime: `pacman -Syu`
закрыл выполняющийся shell. Обновление возвращено в `setup-msys2`, но
установка UCRT64-пакетов оставлена после восстановления кэша. Теперь
ожидается повторная проверка сборки и публикации.

Третий Windows job сохранил пакет OpenSSL в Actions cache и дошёл до шага
сборки. Первой командой в нём не прошла проверка `pkg-config` для p11-kit;
путь proxy DLL теперь берётся из списка файлов установленного пакета.

Четвёртый Windows job также завершился до компиляции: в пакете p11-kit для
UCRT64 отсутствует `p11-kit-proxy.dll`. Сам пакет проверен по архиву MSYS2:
в нём есть `p11-kit-trust.dll` и `p11-kit-1.pc`. Для проверки загрузки выбран
`p11-kit-trust.dll`; Meson получает явный путь к UCRT64 pkg-config файлам.

Пятый Windows job восстановил кэш OpenSSL и дошёл до компиляции, которая
выявила отсутствие `#include <pthread.h>` в `util.h`. По проверенному рецепту
владельца подключение добавлено непосредственно туда; ветка `__GNUC__` в
`endian.h` исключена для Windows, чтобы использовать предусмотренный
fallback вместо отсутствующего `byteswap.h`.

Шестой Windows job с этими патчами дошёл до `interface.c`. Подключение
`windows.h` определило макрос `interface`, конфликтующий с одноимённым полем
контекста провайдера. После Windows-заголовка макрос снимается; проверка
сборки повторяется.

Седьмой запуск прошёл на всех пяти платформах и выпустил обычный Release
№ 14. Кэш OpenSSL для версии 3.6.5-1 повторно использован. Пять архивов
скачаны, SHA256SUMS совпали. В Windows архиве обнаружен пустой `Git commit`
в BUILD-INFO: в MSYS2 shell не оказалось доступной локальной команды Git,
а ошибка внутри heredoc не остановила упаковку. Скрипт теперь берёт
`GITHUB_SHA` в Actions и явно проверяет непустой SHA; верификатор архива
проверяет 40-символьный SHA. Дальше: повторить релиз и проверить метаданные.
