# Состояние проекта

В работе отдельные сборки Windows MSVC с готовым динамическим OpenSSL из
`openssl-vcpkg` для x86, x64 и ARM64. Локальная Linux-проверка изменений
прошла; результаты Windows runners ещё ожидаются. Текущий выпуск № 25
содержит прежние семь целей.

Релизный workflow использует действия кэша и загрузки артефактов на Node 24.
В выпуске № 25 предупреждений Node 20 нет; остаются предупреждения об
очереди macOS ARM64 и об устаревании MSYS2 MINGW32.

В Windows-заголовке PKCS #11 применяется `pack(1)` с восстановлением
прежней упаковки после заголовка. Прямой ABI-тест прошёл на Windows
x86, x64 и ARM64; он отвергает прежний заголовок. Реальный Windows
модуль токена и описанное падение не проверялись.

Матрица dev-релиза включает Windows x86/MINGW32, x86_64/UCRT64 и
ARM64/CLANGARM64. Все три DLL прошли проверку PE Machine, загрузку
через OpenSSL и проверку прямых PE-импортов на своих GitHub runners.

В `main` исправлен вход с заводским PIN при
`CKF_USER_PIN_TO_BE_CHANGED`: провайдер передаёт PIN в `C_Login`.
Также удалены ранний отказ по `CKF_USER_PIN_FINAL_TRY` и локальная
блокировка повторного PIN, ранее отвергнутого токеном. Блокировка по
`CKF_USER_PIN_LOCKED` сохранена.
Локально прошли три прямых unit-теста и проверка CSR на portable SoftHSM
`.76` с профилем Рутокена без `no-deinit`; опубликованный модуль № 21
прошёл ту же проверку и повторно передал неверный PIN в `C_Login`.
На самом Рутокене исправление пока не проверялось.

Текущий dev-релиз: `pkcs11-provider-dev-build-25`, обычный GitHub Release со
статусом Latest. GitHub Actions собрал семь архивов для Linux x86_64/ARM64,
macOS Intel/ARM64 и трёх архитектур Windows. На Linux и macOS прошли три
прямых unit-теста debug-сборки, на Windows — четыре; все готовые
release-модули загрузились через OpenSSL.
Скачанные архивы прошли `SHA256SUMS`; все `BUILD-INFO.txt` указывают тип
`release` и SHA исходного коммита.

В Meson есть три общих прямых unit-теста и четвёртый тест Windows ABI.
Локальная сборка прошла;
GitHub Actions подтвердил Address Sanitizer, Shellcheck, REUSE и csbuild.
`imported-softokn`, остальные сценарии с токенами и сквозные тесты удалены
по решению владельца.

Все Windows цели используют готовые пакеты OpenSSL из своей среды MSYS2.
Перед каждой сборкой workflow сверяет версию пакета; кэш разделён по
среде и версии. В выпуске № 25 использована версия 3.6.5-1 для всех
трёх архитектур. Release-модули не импортируют MinGW pthread и GCC runtime:
они связаны статически. Все три DLL напрямую импортируют только системные
Windows DLL и свою `libcrypto`. DLL OpenSSL не входят в архивы по решению
владельца; приложение должно предоставить общую с провайдером `libcrypto`.
MINGW32 помечен MSYS2 как устаревающая среда без прямой замены.
Точные цели задаёт `.github/workflows/dev-release.yml`.

macOS сборки используют проверенные SHA-256 пакетов conda-forge OpenSSL
3.6.5 для Intel и ARM64. Обе сборки и архивы загрузились через OpenSSL, а
модули импортируют `@rpath/libcrypto.3.dylib`. В выпуске № 19 оба модуля
содержат только относительный `LC_RPATH` `@loader_path/..`; временного пути
GitHub runner нет. Они подписаны после исправления `LC_RPATH`, проверка
подписи и загрузка OpenSSL прошли на обеих macOS архитектурах. В архиве нет
библиотек OpenSSL по решению владельца. Независимая проверка скачанных
модулей показала `minos 11.0` в `LC_BUILD_VERSION` для Intel и ARM64.
Запуск и тесты прошли на runners macOS 15; на macOS 11 запуск не проверялся.

Коммиты форка после `e5ff476` в `main` имеют автора и коммиттера
`code-agent-43824`. Предыдущие релизные теги сохраняют исходные SHA и
историческую атрибуцию, чтобы сведения о сборке в архивах оставались верными.
